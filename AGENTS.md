# Sentinel (gods-eye)

A global security surveillance command center where every part of the loop is AI-driven. Operators orbit a real 3D Earth (Google Photorealistic 3D Tiles), see camera pins anchored to real lat/lon, and click through to synthetic CCTV clips generated by Veo 3.1, analyzed by per-camera Gemini agents.

## Tech Stack

- **Language:** Python 3
- **Web framework:** FastAPI + uvicorn (broker server)
- **AI:** Google Gemini (Managed Agents via `google-genai`), Veo 3.1 (synthetic video)
- **Frontend:** Vanilla HTML/JS served by the broker; Google Maps JS API + Photorealistic 3D Tiles
- **Async transport:** SSE (`sse-starlette`)
- **Config:** python-dotenv

## Setup

```bash
# Create and activate virtual environment (run.sh does this automatically)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-local.txt

# Copy and configure environment
cp .env.example .env
# Edit .env — for stub mode (no API keys needed) defaults already work
# For real mode: add GOOGLE_MAPS_API_KEY, GOOGLE_AI_API_KEY, SENTINEL_MODE=real
```

## Build / Run / Test

```bash
# Launch everything (broker + orchestrator) — recommended
./run.sh

# Manual launch (after activating venv):
# Register agents (one-time for real mode)
python -m orchestrator.register_agents

# Start broker (web server on http://127.0.0.1:8000)
uvicorn broker.server:app --host 127.0.0.1 --port 8000

# Start orchestrator
python -m orchestrator.main
```

`run.sh` handles venv creation, dependency install, agent registration, and starts both processes. Ctrl-C stops both cleanly.

## Project Structure

```

  server.py          # FastAPI server; serves frontend, SSE event stream

  main.py            # Orchestrator loop; drives per-camera agent ticks
  register_agents.py # One-time Gemini Managed Agent registration

  cameras.py         # Camera definitions and state
  severity.py        # Severity scoring logic

  twiml.py           # (Twilio integration stub)
  _lib.py            # Shared utilities

  threat_analyst/    # Gemini Managed Agent definition
api/                 # Vercel serverless functions (empty; stdlib only)

clips/               # Generated/cached Veo clips

run.sh               # Dev launcher script
```

## Architecture & Key Files

- `broker/server.py` — FastAPI app; SSE endpoint streams camera state updates to the browser
- `orchestrator/main.py` — polling loop; calls `agent_runner` for each camera on each tick
- `orchestrator/veo_client.py` — wraps Google Veo 3.1 API; falls back to stub mode if API is unavailable
- `orchestrator/register_agents.py` — registers one Gemini Managed Agent per camera (run once)
- `agents/threat_analyst/` — Managed Agent spec consumed by `register_agents.py`
- Frontend in `earth/` connects to the SSE stream and updates 3D map pins in real time

## Conventions & Notes for Agents

- **Stub mode is the default** — no API keys required; cameras cycle through red/yellow/green automatically
- Real mode requires `SENTINEL_MODE=real` plus valid Google Maps and Google AI API keys in `.env`
- `api/requirements.txt` is intentionally empty (Vercel serverless uses stdlib only)
- `requirements.txt` is also empty (Vercel framework detection artifact); local dev deps are in `requirements-local.txt`
- Managed Agents and Veo 3.1 are preview APIs; the runner auto-falls-back to stub if the SDK shape doesn't match
- Always run through `run.sh` in dev — it handles venv activation and process cleanup
